# Spotify Dash for Android

Native Kotlin and Jetpack Compose explorer for Spotify Extended Streaming History. Android 9 or newer. The app uses the same metric definitions as the web dashboard, with native charts, navigation, file selection, and CSV export.

## Install and import

1. Install **Spotify Dash** from Klobstore, or download the signed `.apk` from [GitHub Releases](https://github.com/xklob/spotify-dash/releases/latest).
2. [Request your Extended Streaming History](../README.md#get-your-extended-streaming-history), download the ZIP, and extract it. Transfer the extracted JSON files to the phone if you downloaded them on a computer.
3. Open the app and tap **Choose JSON files** or **Choose export folder**. Select every audio/video JSON part from the export. The Android file picker grants access only to the selected files or folder.
4. Explore the seven sections, adjust global filters, and save all matching playback records as CSV from History. On phones, **More** opens Habits, Discoveries, and Data & methods. A fictional demo is available before importing your own data.

Importing additional files merges history and removes exact duplicate source records. A real import replaces the fictional demo. Failed imports keep the previously saved dataset. Clearing app data removes the app's copy, leaving the original export files alone. The Android and web apps keep independent local copies; they do not sync through an account.

## Feature coverage

| Section | Android features |
| --- | --- |
| Overview | Listening statistics, monthly/yearly trends, artist mix, top favorites, peaks and streaks |
| Favorites | Search and rank all artists/shows, titles and albums by time or events; inspect dates and skip rates |
| Habits | Hourly and weekday patterns, calendar and weekday/hour heatmaps, devices, countries, content types, end reasons and shuffle comparisons |
| Discoveries | First-recorded artists, familiar listening, yearly taste overlap, replay obsessions, rediscoveries and descriptive correlation |
| Mood & energy | Weekly/monthly trends, smoothing, mood distribution, weekday/hour patterns, earlier/later comparisons, texture, skip/repeat correlations, annual coverage, and track details |
| History | Filtered records, full details, oldest/newest pagination, Spotify links and full CSV export |
| Data & methods | File/folder import, coverage and duplicate accounting, demo, clear data and metric explanations |

Global filters include date range, content type, minimum played duration, search, artist, device, country, shuffle and timezone. Charts provide numeric values or tables alongside the visual view. First-seen dates use the full import, while displayed metrics use the selected filters. See the root README for the definitions and limitations.

## Import mood metadata

Use the web dashboard's **Mood & energy → Fetch next … tracks**, then **Export for Android**, or run `npm run enrich` on the desktop. See the [catalog instructions and metric definitions](../README.md#add-musical-mood-and-catalog-metadata).

Transfer `spotify-dash-metadata.json` (or the desktop `.local-data/metadata.json`) to your phone. Open **Mood & energy → Import metadata** and choose the file. Completed catalog records merge by exact Spotify ID, retaining the newer retrieval. Invalid imports preserve your existing cache. Both history and metadata survive restart; deleting saved history clears both app copies. The original files are left alone.

The Android app makes no API calls. It can export the same metadata format through Android's Save picker. Only music receives mood scores; missing scores remain unknown and coverage is shown. The demo uses deterministic fictional scores, never real catalog estimates. No local audio files are used.

## Local processing

The APK requests no network or broad storage permission. Import, deduplication, analysis and export run off the main thread. Sanitized history is stored in an atomic, compressed file inside the app's private storage. IP addresses, usernames and user-agent strings are discarded before persistence. Android backup and device transfer are disabled for this local data. External Spotify/help links open through the user's browser or Spotify app.

The bundled demo is entirely fictional. Original exports, signing material and device validation data are excluded from Git and APK resources.

## Build

Requires Java 17 and Android SDK 36. Set `ANDROID_HOME` or create an ignored `local.properties` containing `sdk.dir=/path/to/Android/Sdk`.

```sh
cd android
./gradlew testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

Debug builds use package `com.caleb.spotifydash.debug`; releases use `com.caleb.spotifydash`. They can coexist without sharing data.

The core import/analysis/CSV code is independent of Android UI APIs. JVM tests compare its metrics with expectations generated by the web engine from shared fictional records, including DST boundaries, null flags, duplicate records, empty filters and CSV safety. Mood parity covers all three weighting modes, gaps, three-period distinct-track smoothing, missing/partial scores, and DST. To regenerate fixtures, run `npx tsx scripts/generate-android-fixtures.ts` and `npx tsx scripts/generate-mood-fixtures.ts` from the repository root.

The build inspection script verifies the APK's package/version, launcher, signature, alignment, permissions and fictional demo asset:

```sh
python3 scripts/check-android-build.py \
  --apk android/app/build/outputs/apk/debug/app-debug.apk \
  --build-tools "$ANDROID_HOME/build-tools/36.0.0"
```

Run this from the repository root; add `--release` when checking a signed release APK.

See [validation results](VALIDATION.md) for the completed checks. Run instrumentation on a disposable Android emulator; the UI flow replaces the debug app's local dataset with fictional records:

```sh
./gradlew connectedDebugAndroidTest
```

## Signed release

Keep signing files outside the repository. Set `SPOTIFY_DASH_SIGNING_PROPERTIES` to a private properties file with `storeFile`, `storePassword`, `keyAlias` and `keyPassword`. `storeFile` resolves relative to that properties file.

```sh
SPOTIFY_DASH_SIGNING_PROPERTIES=/private/path/signing.properties \
  ./gradlew assembleRelease lintRelease
```

Publish a standalone signed APK, retain the same certificate for updates, and increase `versionCode`. Klobstore reads the package version and signing certificate from the APK; the web release ZIP does not affect Android update detection.
